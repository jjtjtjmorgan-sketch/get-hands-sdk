# Sages and Custom Hands

Sages and Custom Hands are related, but they are not interchangeable.

## Sage

A Sage is a persistent deep worker that coordinates specialist Hands around an outcome. It works with governed memory, explicit authority, and evidence that can be independently reviewed.

A **Sage definition** is the portable, versioned artifact developers will author. It is not the live worker, its private memory, its account bindings, or an authorization token.

Planned public authoring surfaces include:

- composition of specialist Hands and responsibility boundaries;
- requested capabilities and model policy;
- human canon, world evidence, and experience-memory interfaces;
- review, closure, and handoff contracts;
- fixtures, validation, packaging, and compatibility metadata.

## Custom Hand

A Custom Hand is a portable specialist-agent profile. It describes a bounded role, behavior, skills or routines, model policy, and requested capabilities.

A profile will never contain connected-account tokens, live personal memory, private knowledge, or a permission grant. The deployed Hands runtime remains responsible for matching a request to actual approved access.

## Authority rules

- A profile can request a capability; it cannot grant one.
- A discovery match recommends a skill or tool; it cannot execute it.
- Learning can propose a routine; it cannot silently promote owner canon.
- A worker cannot independently certify its own consequential finding.
- Changing model or provider cannot expand recipients, data access, spending, locality, action scope, or approval class.

## Planned creator journey

1. choose a Sage definition or Custom Hand starter;
2. define responsibilities, requested capabilities, stop conditions, and evidence needs;
3. validate the artifact locally;
4. exercise it against public fixtures;
5. preview its marketplace listing;
6. submit an immutable version for review;
7. install an accepted version into an explicitly authorized test environment.

This journey is planned. No public Sage/Profile package or marketplace submission endpoint is claimed today.

## Planned Marketplace objects

The reference Sage Marketplace will keep different kinds of value distinct:

| Object | Meaning |
| --- | --- |
| Sage definition | Portable configuration for a persistent deep worker |
| Custom Hand profile | Portable specialist-agent profile |
| Skill Card | Bounded procedure, tool, and test contract |
| Maintained Domain Pack | Maintained ontology, resolvers, evidence rules, evaluations, and update duties |
| Verified Knowledge Pack | Licensed content with provenance, expiry, and evaluation metadata |
| Routed Sage Outcome | A specified result with acceptance criteria, deadline, data policy, and evidence requirements |

A listing does not silently relicense third-party work and does not confer runtime authorization. Production payments, account state, abuse controls, and commercial routing remain outside the planned public reference implementation.
